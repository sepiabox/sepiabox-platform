| D-045 | 2026-10-20 | **(default)** Camcorder and DVD video. (1) **Types.** `.mod` (MPEG-2 program stream from SD camcorders) and `.vob` are `video/mpeg`; `.tod` and `.m2t` (MPEG-2 transport stream from HD camcorders and HDV) are `video/mp2t`; `.dv` is `video/dv` (IANA). They join the existing `.mts`, `.m2ts` and `.mpg`. Left out for now: `.webm`, `.flv`, `.asf`, `.3g2`, `.mxf`, `.ogv`. **DVD menus.** `VIDEO_TS.VOB` and `VTS_nn_0.VOB` are Other. Title parts (`VTS_nn_1.VOB` on) are separate videos: they are not joined into one title. **No video.** A file with a video extension that holds no footage is left out of `process`: no manifest and no problem. Each file left out in a run is listed with its reason next to the run's problems, on the same output. Files left out by earlier runs and unchanged since are only counted, with a hint; `--list-left-out` lists them too. Three cases are left out (`NoVideoReason`). (a) A tracker-music `.mod`: it has a ProTracker-family tag at offset 1080, and it does not look like MPEG. This is checked without FFmpeg (`TrackerModule.IsTrackerModule`). Untagged 15-sample Soundtracker modules have no tag. They reach ffprobe, which reports them as a problem when FFmpeg cannot read modules, or leaves them out when it can and finds no video. (b) No video stream: ffprobe finds none, even after a second probe with a 100 MB / 100 s window, in a file that does not look like MPEG. A second probe also follows a first one that finds a video stream without a picture size; if that longer probe then finds no stream, the file is a problem, never left out. (c) Cover art only: every video stream ffprobe finds is an attached picture (`attached_pic`), with no second probe. **Looks like MPEG** (`MpegSignature`) means an MPEG system or video start code at offset 0 (`00 00 01` then `BA`, `BB`, `B3` or `C0`–`EF`; an MP4 box can also start `00 00 01`), or transport stream sync bytes three packets in a row: at 0, 188 and 376, or at 4, 196 and 388 for AVCHD's 192-byte packets (two when the file is too short for a third). A file whose start cannot be read is a problem, not "not MPEG". Such a file is never left out for (a) or (b): a sound-only or picture-less MPEG file is more likely a damaged camcorder clip, so it is reported as a problem and keeps its manifest. The state stores a left-out file's status and reason, so an unchanged one is not read again and its reason is shown on later runs. A left-out row without a reason was written under earlier, weaker rules, so that file is read again once. `process --retry-left-out` reads them again, for example after installing an FFmpeg build with more decoders. The source files are not touched, since their modification time is the only date evidence some camcorder files have. A manifest an earlier run wrote for it (for example while FFmpeg was missing) loses this source, and with its last source the manifest and derivatives are deleted. Blobs already uploaded stay in storage: that is the existing stale-source follow-up (D-032). A file ffprobe cannot read at all stays a problem, since it may be a damaged camcorder file. `scan` counts `.mod` by extension only, so its video total may include tracker files. (2) **Aspect and interlacing.** The display size comes from the stream: the pixel aspect ratio (`sample_aspect_ratio`) is applied to the width before rotation. A 16:9 PAL clip stored as 720x576 is 1024x576, and HDV or AVCHD 1440x1080 is 1920x1080. Ratios of `0:1` or outside 1/4–4 are ignored. JVC `.MOI` sidecars are not read; some Everio models keep the 16:9 flag there while the MPEG-2 header says 4:3, and the owner's renamed files no longer have them. The poster frame and the 720p version go through `yadif=deint=interlaced,scale=W:H,setsar=1`. Only frames flagged as interlaced are deinterlaced, and the output has square pixels at the display size. yadif runs in mode 0: one frame per frame, so 50i becomes 25p. This is deliberate for a proxy; progressive footage flagged as interlaced (PsF) is slightly softened. (3) **Poster fallback.** When the seek to 10% of the duration gives no frame, the poster is taken from the first frame. That covers FFmpeg succeeding without output, failing, or leaving an empty file, as with a transport stream with one keyframe or sound longer than the picture. When the first frame also gives nothing, the file is a problem whose manifest is kept, as for any derivative failure. (4) **CR2.** CR2 files stay photos. Magick.NET reads them from a stream with no format hint and only the first image. With the real header (IFD0 at offset 16, "CR" version 2) it uses the TIFF coder and decodes the camera's full-size JPEG in IFD0 (old-style JPEG compression). It does not demosaic the sensor data with LibRaw; a test asserts the TIFF coder on a fixture laid out like a real file. (5) **Follow-ups.** Derivatives versioning: a file processed before this change keeps its old derivatives, since `process` only makes the derivatives a manifest lacks; no work folder existed yet when this was decided. Others: a per-source aspect override if the owner's JVC clips come out 4:3; a test on a real CC0 CR2 (raw.pixls.us is not reachable from the development sandbox); probing before hashing large files that turn out not to be video. | Leave them as Other; keep stored pixels and let players stretch; always deinterlace; yadif mode 1 (50p); decode CR2 with LibRaw; rely on FFmpeg to recognise tracker modules | The owner's drive holds 1,692 `.mod` files (139 GB) that were skipped. Browsers ignore the pixel aspect ratio in MP4, so an anamorphic proxy would look squashed. Deinterlacing only flagged frames leaves progressive video untouched, and 25p halves the proxy's frames. The camera's JPEG is faster than a demosaic and already has the camera's colour rendering, which is all a 1280 preview needs. FFmpeg's module support depends on the build (libopenmpt). |
