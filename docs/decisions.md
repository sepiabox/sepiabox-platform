| D-036 | 2026-10-19 | **(default)** A manifest blob is never overwritten blindly. **Every writer of a manifest blob — `upload` today, the worker processing cloud files in S-036 and any later one — must go through `ManifestStore.WriteMergedAsync` (Sepiabox.Pipeline).** It reads the stored manifest and validates it with `ManifestValidator` (the same check as the import), merges, skips the write when the merged JSON equals what is stored (so a re-upload changes no ETag and triggers no import), and otherwise writes only if the blob is unchanged (`If-Match` on its ETag, `If-None-Match: *` when new); on 409/412 it reads and merges again, up to 5 attempts with a randomised backoff (50–250 ms × attempt). A stored manifest that cannot be read or describes another asset, or 5 conflicting attempts, is a problem for that asset only: it is not marked uploaded and is retried next run. Merge (`ManifestMerge`): union of sources by file identity (type, name, path with `/` as separator, case-sensitive), the newer `modifiedAt` winning; union of derivatives by name, the incoming one winning on the same name and none dropped; the asset's description (date, place, size…) comes from the incoming manifest unless it has no derivatives while the stored one has, which marks an unfinished run (a video waiting for FFmpeg, D-029, or a photo that did not decode, D-028). **Rule for later stories:** `embeddings` merge by model key, the incoming value winning per key (S-015); `faces` come from the side with `facesProcessed: true`, the incoming one if both (S-018). **Trade-off of add-only sources:** no source is ever lost by a merge, but a file renamed or moved on a drive leaves its old path as a stale source until a removal mechanism exists; the planned one is a `removedAt` tombstone on the source, merged like `modifiedAt` (newer wins), so a removal survives the union. | Overwrite and rely on the import's add-only sources (D-032); last writer wins | Two drives uploaded before the next import would otherwise lose the first drive's sources and derivatives for good; ETags make the merge safe with uploads from two computers at once; stale paths are a smaller harm than lost ones. |
| D-037 | 2026-10-19 | **(default)** Catalog times: `captured_at` is `timestamp without time zone` holding the camera's wall-clock time exactly as `process` writes it; a manifest whose `capturedAt` has an offset or `Z` is rejected by the schema (and reported by the import), never converted. `assets.imported_at` is set once, when the asset first enters the catalog; `assets.updated_at` changes on every import that touches it. Source `modified_at` and import times are UTC `timestamp with time zone`. | Accept offsets and convert to local or UTC; one `imported_at` overwritten on each import | `process` never writes an offset, so one means a foreign writer; converting would silently shift photos across midnight. Keeping the first import time answers "what is new in the library". |

| D-039 | 2026-10-19 | **(default)** Pages never contain storage links. The browser asks the web (`/fotos/{id}/{derivative}`, `/fotos/{id}/original`), which signs a read-only, single-blob SAS at that moment and answers 302. Derivatives: expiry rounded down to a 5-minute window plus 15 minutes (10–15 min left), so the URL is stable in the window, with `Cache-Control: private, max-age=600`. Originals: 5 minutes, `no-store`, downloaded under the first source's file name and the catalog's content type (`rscd`/`rsct`).
